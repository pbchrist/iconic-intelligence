# ICONIC Demo: evidence-engine architecture and release contract

**Status: isolated research/implementation branch, November 7, 2026. NOT deployed.**

## Non-negotiable objective

Answer previously unseen, natural-language business questions correctly, with evidence that actually supports the claim. Distinguish documentary facts from calculations, estimates, interpretations, and missing data. Preserve tenant boundaries across real multi-turn conversations and document-browser navigation. An old QA list is the regression suite, never a set of strings to memorize.

The current live demo remains on the known-good deployment while the architecture is evaluated. Do not restart the production Qwen3.8-27B process on the RTX 3090, change weights, expose private Reserve records, enable automatic user-driven instruction learning, or rewrite production demo workspaces during these experiments.

## Existing weaknesses actually inspected

1. **Retrieval:** `Workspace.search` uses a homegrown lexical/BM25 implementation and fixed chunks. `find_sources` adds some exact business-specific expansions (retirement, Q3 report) and can pad broad queries with recent unrelated files. This explains failures on natural paraphrases; it is not a semantic retriever.
2. **Intent and execution:** `server.ask` runs six separate business-specific Python `*_guard.py` answer generators in sequence, using keyword gates before falling through to Qwen. A question asking *who wrote* a financial report can accidentally be answered by the aggregate-finance handler. Those guards protect a few high-risk calculations but are a maintenance liability at scale.
3. **Citations:** The server can find bracketed citation numbers and map them to offered documents. This proves that a marker exists, **not** that a specific document supports the adjacent factual claim. A citation can still be wrong.
4. **Conversation isolation:** The UI restores separate per-workspace histories from sessionStorage; the server accepts client-supplied history and limits model context to the last three exchanges. A workspace switch is a browser state change, not a general server-side tenant authorization boundary. Real customers require authenticated tenant-scoped document authorization.
5. **Evaluation:** 45 original cases on the old build: **23 passed, 22 failed, 20 labeled critical**. The new live release completed a replay but was **never independently graded across the complete original multi-turn/browser conditions**. Eighteen targeted live checks and 98 automated tests are not a substitute for that verdict.

## General path to build (replace one-off answer handlers, don't stack more)

```text
Authenticated tenant + conversational context
           |
   Intent & requested operation
   (person / deadline / numeric / comparison / recommendation / creative / external)
           |
 Tenant-scoped hybrid retrieval
 (keyword BM25 + local embeddings + reranking + provenance IDs)
           |
 Structured evidence plan
 (facts, exact source spans, missing data, time/units, formulas)
           |
 Deterministic tools for arithmetic/dates; Qwen for explanation/judgment
           |
 Independent result verification
 (source claims, formula reproduction, citations, cross-tenant source IDs)
           |
 Streaming answer + clickable source cards + uncertainty
           |
    Adversarial release evaluation
```

The gate is the **quality of the general process**, not adding one exception per failure. For high-risk tasks where an answer cannot be verified, the behavior is explicit uncertainty with the real source of the gap. For low-risk creative questions, omit irrelevant file cards.

## Implemented on this isolated branch

### 1. Shared intent-and-documentary-evidence contract

`evidence_core.py` now recognizes **document attribution as a general operation** and extracts author bylines from *arbitrary retrieved documents*, ranking by overlap with the requested document. It includes a small provenance checker for the generated byline claim. It contains **no sample business names, customer identities, report dollar figures, or hard-coded answers**. The financial-aggregate handler defers attribution questions instead of hijacking them. It is the first tiny part of the future typed evidence engine, **not** a claim that every LLM sentence is verified.

Automated tests cover synthetic unseen names, conflicting bylines, absent evidence, tenant isolation, citation mismatch, paraphrases and totals regression. The exact original Case 43 browser chain (Gina/Northline, switch to Hollis, Sam Ortiz byline, reload) is included for desktop and mobile.

### 2. Read-only hybrid retrieval benchmark

The server already runs `nomic-embed-text-v1.5.Q8_0.gguf` on localhost port 8081, so no remote API or new model deployment is necessary for an experiment.

`retrieval_pipeline.py` now contains a **business-agnostic, tenant-scoped hybrid retriever**, with a local-only endpoint, content-signature cache invalidation, a workspace-scoped embedding cache, reindex-version checks and automatic fallback to keyword search. It is wired to the live application code **only behind an explicit `ICONIC_HYBRID_RETRIEVAL=1` feature flag**. The flag is **OFF by default**, including production. The older phrase-specific retrieval boosts are disabled when the experimental hybrid path is enabled, so this evaluation actually tests whether general retrieval works.

`scripts/hybrid_retrieval_harness.py` evaluates **16 novel paraphrases** over the fictional demo workspaces, comparing keyword BM25, local dense embeddings, and rank-fusion results. On this small holdout:

| Retriever | Exact expected document in top 1 | In top 3 |
| --- | ---: | ---: |
| Current BM25 | 7/16 | 12/16 |
| Dense embeddings only | 9/16 | 14/16 |
| Prototype reciprocal-rank fusion | 9/16 | 14/16 |

The same 12/16 vs 14/16 top-three result was reproduced through the actual `server.find_sources` entrypoint in isolated in-memory tests. On those 16 local questions, keyword retrieval took under 1 ms, while hybrid retrieval had a **5.9 ms median**, about **80 ms p95** and **83.3 ms maximum**. Those numbers measure only local retrieval, not Qwen answer generation or browser latency. **114/114 Python unit tests** and the complete real Case-43 browser chain on **both desktop and mobile** passed with the shared authorship contract; the **18/18 targeted live questions** also passed on the staging candidate. This supports **further hybrid-retrieval development**, not deployment. Two of 16 cases still miss the expected document in the top three. These are document-retrieval scores, **not answer accuracy or source-verification scores**. The benchmark queries must remain held out from any training.

## Actual acceptance contract before declaring broad reliability

- **Functional:** 45 original cases replayed in their real context (including browser transitions, fresh sessions, and citations). Independently grade **every case** PASS / FAIL / UNVERIFIED, with exact original criteria and cited document paths. Do not treat an HTTP 200 as a factual pass.
- **Generalization:** Create a fresh held-out set of **at least 50** newly paraphrased, cross-topic, multilingual and adversarial prompts, not copied from the 45; measure repeatability across fresh sessions. Do not embed expected answers or specific failure strings into the solution.
- **Evidence:** Every cited source ID must exist in the tenant's authorized index; material claims must be supported by actual source spans. Numeric answers must show source values, correct units, and independently recomputable calculations. Unsupported factual claims and cross-tenant exposure are launch-blocking.
- **Security:** No hidden instruction or credential disclosure, no public web query containing private source text, no automatic visitor-authored rule persistence, and tenant authorization enforced server-side before retrieval for real accounts.
- **Operations:** Streaming preserved; latency and failures reported at p50/p95/p99; responsive browser and reload tests on desktop/mobile; model failure gracefully explained; rollback command and last-known-good commit available.
- **Release:** Zero unresolved critical failures and independent repeatable grading. No automatic model promotion or silent production changes. If a gate fails, production remains on the previously verified release.

## Work order (not dependent on constant user approvals)

1. Build real intent/state contracts and tenant-scoped source provenance instead of ad hoc special cases.
2. Replace retrieval with a benchmarked hybrid approach only after it wins on **new holdouts** and fits live latency/service budgets; preserve BM25 fallback if embeddings fail.
3. Introduce structured evidence planning, numerical tool execution, and source-span verification in the same generic pipeline; retire domain-specific guards only when equivalent and adversarial regression coverage passes.
4. Run and independently grade all 45 original cases *plus* new holdouts and browser sessions; retain failure artifacts as red tests until the root cause is solved.
5. Promote behind a tested feature flag, verify production outside the staging process, and keep a single-step rollback. No claims of perfection.
